Extract

/stardust:extract <url>

Read the site you already have.

Direct

/stardust:direct

One sentence in. A direction out.

Tell it what you want in plain words: warmer, more editorial, keep our type. Direct reads the capture, keeps your palette and fonts unless you ask for a rebrand, researches references when it can, and rolls the seed for whatever is still open. It writes the target spec and its reasoning, so you can argue with it.

Prototype

/stardust:prototype

Before and after, side by side.

Prototype renders one page of the redesign as a single HTML file and puts it next to the capture. Then it runs impeccable's craft loop: critique, audit, adapt to six viewports, check the motion. It rejects template-looking output. You pick, annotate, and re-run. Approve it, and migrate carries the design to every page as static HTML.

Replica

/stardust:replica <url>

The site you have, rebuilt clean.

Replica reads the live site and recreates one page per template as clean HTML and CSS, never a DOM copy. It gates each one against the original at two breakpoints: structure, visuals, a stitched pixel diff. The only design changes allowed are the ones you list. Then migrate clones the rest of the pages.

Deploy

/stardust:deploy

One page into blocks.

Deploy takes one page of static HTML and turns each section into an Edge Delivery block with its own CSS, and the copy into authorable content. It writes both through the Document Authoring API, previews, publishes, then reads the live page back and checks it. A page counts as deployed only when that check passes.

Rollout

/stardust:rollout

The whole site, then the check.

Rollout runs deploy across the migrated tree. It keeps a ledger of what shipped and what is left, shares blocks across pages instead of forking them, adds the sitemap and redirects, and audits every link. When it is done, qa sweeps the live site and reports what it finds. It never edits.
